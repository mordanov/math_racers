# Implementation Plan: AI Opponents

**Branch**: `005-ai-opponents` | **Date**: 2026-08-10 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/005-ai-opponents/spec.md`

## Summary

Add 5 AI personality types with checkpoint-aware, seeded simulation to the frontend race engine, and expose a `GET /api/v1/opponents/personalities` endpoint on the backend. All simulation stays client-side; the backend serves personality configuration only. No database migrations required.

## Technical Context

**Language/Version**: TypeScript 5.4 (frontend), Python 3.12 (backend)
**Primary Dependencies**: React 18 + Vitest 3 (frontend); FastAPI + Pydantic 2 (backend)
**Storage**: N/A — no new tables; personality definitions are static constants
**Testing**: Vitest (frontend unit), pytest (backend unit + integration)
**Target Platform**: Browser (Chromium/Firefox/Safari), Linux (backend)
**Project Type**: Web application (frontend + backend)
**Performance Goals**: Simulation per checkpoint < 1ms; personalities endpoint < 50ms p95
**Constraints**: Zero backend calls during active race; simulation deterministic per seed
**Scale/Scope**: 1–5 AI opponents per race, 8 checkpoints per race

## Implementation Strategy

### Phase order

1. **Frontend types first** — extend `AiPersonality` in `types.ts`; all downstream code references the new shape.
2. **Frontend simulation** — update `aiRunner.ts` with the new `sampleResponseTime` + `speedMultiplier` logic and `checkpointIndex` parameter.
3. **Frontend personalities module** — add `personalities.ts` with the 5 constants.
4. **Frontend engine integration** — update `raceEngine.ts` for per-opponent RNG and tiebreaker.
5. **Frontend tests** — add/update tests to cover new behaviour.
6. **Backend personalities module** — add `app/opponents/`, schemas, constants.
7. **Backend endpoint** — add router, register in `main.py`.
8. **Backend tests** — unit + integration tests for the endpoint.

### MVP scope

User Story 1 (race simulation with all 5 personalities) is the MVP. US2 (visibly distinct personalities) emerges from US1 naturally once `speedProfile` is wired in. US3 (personalities endpoint) is independent and can be delivered in parallel with US1–US2.

### Key invariants to preserve

- `createRng(seed + 1)` is already used for the single-AI case; per-opponent seeding with `seed + participantIndex + 1` preserves backward compatibility for the 1-AI-opponent case (participant index 0 for a race with human at index 0 and AI at index 1 → `seed + 2`). **Caution**: verify existing test fixtures match the new index-based seeding.
- `simulateAiObstacle` is called from `raceEngine.ts` only; updating its signature there is the only call-site change.
- The old `baseResponseTimeMs` and `responseTimeVarianceMs` fields are retained on `AiPersonality` for test backward compatibility; the new implementation uses `speedProfile`-driven logic instead.
