# Implementation Plan: Game Modes

**Branch**: `006-game-modes` | **Date**: 2026-08-10 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/006-game-modes/spec.md`

## Summary

Implement the four game modes (Quick Race, Championship, Training, Duel) by: (1) extending the existing race engine and `POST /api/v1/races` to support nullable `position` for Training; (2) adding a `Championship` + `ChampionshipRace` domain with three new API endpoints; (3) wiring XP calculation in the race engine; and (4) adding a frontend avatar guard at Race Setup. No new frontend pages are built in this feature — the engine and API contracts are the deliverable; UI screens are a separate feature scope.

## Technical Context

**Language/Version**: TypeScript 5.4 (frontend), Python 3.12 (backend)
**Primary Dependencies**: React 18 + Vitest 3 (frontend); FastAPI + Pydantic 2 + SQLAlchemy 2 + Alembic (backend)
**Storage**: PostgreSQL — one Alembic migration (nullable `position` on `race_participants`; new `championships` and `championship_races` tables)
**Testing**: Vitest (frontend unit), pytest (backend unit + integration)
**Target Platform**: Browser (Chromium/Firefox/Safari), Linux (backend)
**Project Type**: Web application (frontend + backend)
**Performance Goals**: Championship standings endpoint < 100ms p95; no new constraints on race submission
**Constraints**: Zero backend calls during active race (existing invariant preserved); Championship PATCH must atomically auto-complete on final race

## Implementation Strategy

### Phase order

1. **Backend migration** — Alembic migration for nullable `position` + new championship tables. All downstream code depends on schema.
2. **Backend races update** — update `RaceParticipant` model + `ParticipantSummaryRequest` schema to allow `null` position; add validation that null is only allowed in training mode.
3. **Backend championships domain** — `app/championships/` module: models, schemas, repository, domain service (points table, standings, auto-complete).
4. **Backend championships endpoint** — `presentation/api/v1/championships.py` router; register in `main.py`.
5. **Backend unit tests** — domain service: points table values, standings ordering, auto-complete trigger.
6. **Backend integration tests** — POST/GET/PATCH championship endpoints; POST /api/v1/races with null position (training).
7. **Frontend types** — `ParticipantSummary.position → number | null`.
8. **Frontend engine** — XP formula in `getSummary()`; training `forceComplete()` branch.
9. **Frontend tests** — XP per mode, training summary shape, forceComplete transition.

### MVP scope

Quick Race (engine + result submission) is already implemented. The MVP for this feature is Championship (new domain). Training nullable position and XP calculation are small add-ons. Duel requires no new backend work.

### Key invariants to preserve

- Existing `POST /api/v1/races` tests pass without modification (only additive change: nullable position allowed when mode=training).
- `raceEngine.ts:getSummary()` still returns a `RaceSummary` — shape is backward compatible (position is now `number | null` which is a widening, not breaking change for callers that only use non-training modes).
- Championship standings positions are recalculated from scratch on each `GET` / `PATCH` response — no cached state to invalidate.
