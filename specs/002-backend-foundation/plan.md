# Implementation Plan: Backend Foundation

**Branch**: `002-backend-foundation` | **Date**: 2026-08-09 | **Spec**: [spec.md](spec.md)

---

## Summary

Implement the accounts domain: email/password authentication, a two-role model (parent / administrator), administrator-only approval workflow for new registrations, JWT access tokens with opaque refresh token rotation, and startup seeding of a default administrator. Builds on top of the infrastructure foundation already delivered in sprint 001 (FastAPI app factory, config, logging, correlation-ID middleware, health endpoint, Alembic, Redis worker).

---

## Technical Context

**Language/Version**: Python 3.12 (pyproject.toml requires >=3.12; production runs 3.13 per ADR-002)
**Primary Dependencies**: FastAPI, SQLAlchemy asyncio, Pydantic v2, Alembic, Redis, asyncpg (all existing); new additions: `PyJWT[crypto]>=2.13.0`, `bcrypt>=4.2.0`
**Storage**: PostgreSQL — two new tables: `accounts`, `refresh_tokens`
**Testing**: pytest + pytest-asyncio (existing); integration tests hit real DB via CI service sidecar
**Target Platform**: Linux container (python:3.12-slim)
**Project Type**: Web service (modular monolith, ADR-002)
**Performance Goals**: Login/register < 500ms p95; health endpoint < 100ms p95 (existing)
**Constraints**: No hardcoded secrets; bcrypt work factor 12; refresh token cookie scoped to `/api/v1/auth/refresh`
**Scale/Scope**: Initial deployment; hundreds of accounts expected

## Key Implementation Notes

1. **Startup seeding order**: `_run_migrations()` → `_seed_default_admin()` → `recover_pending_jobs()`. The seeding function runs inside the FastAPI lifespan after migrations confirm the `accounts` table exists.

2. **Minimum-administrator guard**: Implemented in `DeleteAccountUseCase` and (if a demote-role endpoint is added later) any role-change path. Query: `SELECT COUNT(*) FROM accounts WHERE role = 'administrator' AND approval_status = 'approved'`. If result would become 0, raise `LastAdministratorError` → HTTP 400 `LAST_ADMINISTRATOR`.

3. **Token storage**: Only the SHA-256 hash of the opaque refresh token UUID is stored in the DB. The raw UUID is sent to the client in the cookie. On refresh, the server computes `sha256(raw_token)` and looks it up.

4. **Auth middleware**: `app/presentation/api/middleware/auth.py` decodes the Bearer JWT, fetches the account row (to confirm it still exists and is approved), and injects a `CurrentAccount` typed object into `request.state`. Endpoints declare `account: CurrentAccount = Depends(get_current_account)`. Administrator-only endpoints additionally call `require_administrator(account)`.

5. **Error handler registration**: `app/main.py` registers exception handlers for `DomainError` subtypes → HTTP status mapping per the hierarchy in `docs/engineering/spec-backend-foundation.md`.

6. **alembic/env.py update**: Import `Base.metadata` once the ORM models exist so `autogenerate` works for future migrations. For now, migrations 0002 and 0003 are written manually (consistent with migration 0001 which was also hand-written).
