# Math Racers — Art Bible

# Part I — Complete Visual Language

**Version:** 1.0

---

# 1. Purpose

This document defines the visual identity of **Math Racers**.

It is the single source of truth for:

- artists;
- AI image generation;
- UI designers;
- animators;
- Claude Code prompts;
- future contributors.

Every illustration, icon, animation and interface element must follow this document.

The objective is that a player can immediately recognise a screenshot as belonging to **Math Racers**.

---

# 2. Design Philosophy

The visual language follows one simple principle.

> **"Pixar-quality warmth with Nintendo-level readability."**

Children should immediately perceive the world as:

- safe;
- cheerful;
- colourful;
- energetic;
- optimistic.

Nothing should appear realistic.

Nothing should appear frightening.

Nothing should appear sarcastic.

---

# 3. Emotional Goals

Every screen should communicate one or more of the following emotions.

Primary emotions:

- Joy
- Curiosity
- Energy
- Confidence
- Safety
- Wonder

Secondary emotions:

- Excitement
- Surprise
- Pride
- Discovery
- Friendship

Negative emotions should never dominate.

---

# 4. Visual Keywords

The complete project can be summarised using these words:

- playful
- rounded
- expressive
- colourful
- premium
- polished
- soft
- energetic
- optimistic
- readable
- approachable
- magical

Whenever a design decision is uncertain, these words should guide it.

---

# 5. Inspirations

The visual language is inspired by (not copied from):

### Animation

- Pixar
- DreamWorks
- Disney Animation

### Games

- Mario Kart
- Animal Crossing
- Fall Guys
- Nintendo Sports
- Mario Party

### Illustration

- Modern children's books
- High-end educational apps
- Contemporary storybook illustration

The goal is to achieve a timeless visual identity rather than following temporary trends.

---

# 6. Visual Style

The project uses:

## Stylised 3D Illustration

Images should look like professionally rendered 3D animation.

Not:

- flat illustration;
- anime;
- comic book;
- realistic painting.

Think:

"A feature-length animated movie rendered into illustrations."

---

# 7. Shape Language

Everything follows rounded geometry.

Preferred:

○ circles

⬭ rounded rectangles

soft curves

smooth silhouettes

Avoid:

sharp triangles

thin spikes

hard edges

aggressive geometry

Children instinctively associate rounded shapes with safety.

---

# 8. Silhouette Rule

Every important object should be recognisable from its silhouette.

Examples:

- avatars;
- trophies;
- buttons;
- trees;
- stadium decorations.

If the silhouette is removed from colour, the object should remain identifiable.

---

# 9. Visual Hierarchy

Players should instantly understand where to look.

Priority order:

```
Characters

↓

Mathematics

↓

Interaction

↓

Animation

↓

Environment

↓

Decorations
```

Backgrounds must never compete with gameplay.

---

# 10. Colour Philosophy

Colour communicates emotion before information.

Primary objectives:

- optimism;
- clarity;
- excitement;
- accessibility.

Every colour should feel intentionally chosen.

Avoid visual noise.

---

# 11. Palette Characteristics

The palette should be:

- vibrant;
- saturated;
- warm;
- high contrast;
- harmonious.

Avoid:

- muddy colours;
- greyscale interfaces;
- washed-out tones;
- overly neon colours.

---

# 12. Primary Palette

Core colours:

Sky Blue

Golden Yellow

Grass Green

Coral Orange

Warm Red

Soft Purple

Turquoise

White

These colours become the identity of the game.

---

# 13. Secondary Palette

Supporting colours:

Mint

Peach

Lavender

Cream

Sand

Light Teal

Warm Brown

These enrich environments without overwhelming the player.

---

# 14. Neutral Colours

Neutrals should remain warm.

Avoid cold grey interfaces.

Preferred neutrals:

Warm White

Light Cream

Soft Beige

Light Stone

Warm Grey

Dark Charcoal

---

# 15. Colour Usage

General rule:

```
70%

neutral

20%

primary

10%

accent
```

Accent colours should attract attention only to important interactions.

---

# 16. Contrast

Contrast must support readability.

Examples:

Correct Answer

Bright Green

Incorrect

Warm Orange

Selected

Blue Glow

Disabled

Soft Grey

Never rely on colour alone.

Always combine with:

- icons;
- animation;
- movement.

---

# 17. Lighting

Lighting resembles an animated movie.

Characteristics:

- warm;
- sunny;
- soft;
- global illumination;
- subtle rim light.

Avoid:

dramatic shadows

dark scenes

harsh spotlights

The world should always feel welcoming.

---

# 18. Shadows

Shadows should be:

- soft;
- slightly blurred;
- subtle.

Avoid:

hard black shadows.

Shadows create depth, not drama.

---

# 19. Materials

Preferred materials:

- polished plastic;
- painted wood;
- soft fabric;
- smooth rubber;
- grass;
- colourful stone.

Everything should appear pleasant to touch.

---

# 20. Surface Detail

Textures remain simplified.

Avoid:

- photographic textures;
- scratches;
- dirt;
- excessive realism.

Stylisation has priority over realism.

---

# 21. Outlines

Characters should not use comic-style black outlines.

Instead:

- colour separation;
- lighting;
- soft ambient occlusion.

The result appears modern and premium.

---

# 22. Depth

The world should feel layered.

Foreground

↓

Gameplay

↓

Background

↓

Sky

Every layer has different visual complexity.

---

# 23. Background Philosophy

Backgrounds create atmosphere.

They never distract from:

- runners;
- mathematics;
- UI.

Players should subconsciously enjoy the scenery without looking away from the race.

---

# 24. Stadium Style

The stadium resembles an international children's sports festival.

Characteristics:

- colourful banners;
- balloons;
- flags;
- flowers;
- trees;
- happy spectators.

No advertising.

No commercial branding.

---

# 25. Sky

The sky communicates mood.

Version 1.0 primarily uses:

Bright blue sky

Soft clouds

Warm sunlight

Future seasons may introduce variations.

---

# 26. Vegetation

Plants should be:

- rounded;
- stylised;
- vibrant.

Examples:

Trees resemble oversized broccoli crowns.

Bushes resemble fluffy clouds.

Flowers are simplified.

---

# 27. Architecture

Buildings are playful.

Examples:

- curved roofs;
- oversized windows;
- colourful facades.

Avoid realistic urban environments.

---

# 28. Scale

Objects should exaggerate proportions.

Examples:

Trees

110%

Flowers

140%

Benches

120%

This creates a storybook world.

---

# 29. Motion Language

Even static artwork should imply movement.

Examples:

- curved paths;
- leaning trees;
- waving flags;
- flowing banners.

Nothing should feel rigid.

---

# 30. Visual Density

The interface should breathe.

Empty space is valuable.

Avoid clutter.

Children should identify interactive elements within one second.

---

# 31. Consistency

Every asset should appear to belong to the same universe.

A new illustration should be indistinguishable from launch artwork.

Consistency is more important than individual creativity.

---

# 32. Accessibility

The visual language must support:

- colour blindness;
- reduced vision;
- younger children;
- cognitive accessibility.

Use:

- large shapes;
- strong contrast;
- simple silhouettes.

Complex visual metaphors should be avoided.

---

# 33. Future Expansion

Future content should feel native.

Examples:

New stadiums

New avatars

New subjects

New achievements

New UI

should all follow the same visual language without requiring redesign.

---

# 34. Visual Principles

Every asset should satisfy:

- instantly readable;
- emotionally positive;
- premium quality;
- highly expressive;
- colourful;
- rounded;
- playful;
- timeless.

---

# 35. Success Criteria

The visual language is considered successful if:

- children immediately recognise Math Racers from a single screenshot;
- the game feels joyful even before interaction;
- every screen appears suitable for a premium animated film;
- parents perceive the artwork as beautiful rather than merely "for children";
- new AI-generated assets blend seamlessly with existing artwork.

The visual identity should make the game feel like a living animated world rather than a collection of individual illustrations.

---

**End of Part I — Complete Visual Language**

# Math Racers — Art Bible

# Part II — Character Design Rules

**Version:** 1.0

---

# 1. Purpose

This document defines every rule for designing characters in **Math Racers**.

It applies equally to:

- AI-generated avatars;
- promotional artwork;
- future NPCs;
- achievements;
- loading illustrations;
- story mode.

Every character in the game must feel like it belongs to the same animated universe.

---

# 2. Design Philosophy

Characters should immediately communicate:

- kindness;
- confidence;
- optimism;
- curiosity;
- energy.

The goal is not realism.

The goal is emotional connection.

Players should feel that every avatar could become their favourite.

---

# 3. Character Pillars

Every avatar should be:

- memorable;
- readable;
- expressive;
- charming;
- athletic;
- unique;
- child-friendly.

No avatar should look aggressive or intimidating.

---

# 4. Core Personality

Every character is fundamentally good.

Differences come from personality rather than morality.

Examples:

Fast

Curious

Shy

Cheerful

Calm

Determined

Playful

Inventive

Competitive (friendly)

No character should ever be evil.

---

# 5. Universal Anatomy

All species share the same design language.

```
Large head

↓

Expressive face

↓

Compact torso

↓

Long legs

↓

Medium-length arms

↓

Large hands

↓

Large feet
```

This improves animation readability.

---

# 6. Body Proportions

Recommended proportions:

Head

≈ 40% of total height

Torso

≈ 25%

Legs

≈ 35%

The large head maximises emotional expression.

---

# 7. Silhouette Rule

Each avatar must be recognisable in pure black silhouette.

Recognition should remain possible without:

- colour;
- texture;
- clothing.

If the silhouette is unclear, redesign the character.

---

# 8. Eyes

Eyes are the most important feature.

Requirements:

- large;
- bright;
- expressive;
- symmetrical;
- high contrast.

Avoid tiny or realistic eyes.

Children instinctively connect with expressive eyes.

---

# 9. Eyebrows

Eyebrows communicate emotion.

They should be:

- rounded;
- soft;
- flexible.

Avoid sharp angular eyebrows.

---

# 10. Nose

Noses remain simplified.

Examples:

- rounded button nose;
- small animal nose;
- soft triangle.

Avoid realistic human anatomy.

---

# 11. Mouth

Mouths should support exaggerated expressions.

Smiles are wide.

Neutral expressions remain friendly.

No sharp teeth should be visible.

---

# 12. Ears

Species define ear shapes.

Examples:

Fox

Tall triangular ears

Rabbit

Long floppy ears

Bear

Rounded ears

Cat

Soft pointed ears

Mouse

Large circular ears

Ears contribute strongly to silhouette recognition.

---

# 13. Hair

Hair should be stylised.

Requirements:

- simplified shapes;
- soft curves;
- readable volume.

Avoid:

- realistic strands;
- highly detailed hairstyles;
- sharp spikes.

Hair should remain recognisable at small sizes.

---

# 14. Fur

Animal-inspired characters use stylised fur.

Characteristics:

- smooth;
- soft;
- simplified.

Avoid highly detailed fur rendering.

The illusion of softness is more important than individual hairs.

---

# 15. Skin

Human-like skin should appear healthy and warm.

All skin tones should receive equal artistic attention.

No tone should appear more saturated or less polished than another.

---

# 16. Colour Harmony

Each avatar follows a restrained palette.

Typical distribution:

```
Main colour

60%

Secondary colour

25%

Accent colour

10%

Small details

5%
```

Too many colours reduce recognisability.

---

# 17. Species Identity

Species should be recognisable even without accessories.

Primary recognition comes from:

- ears;
- tail;
- face;
- proportions;
- silhouette.

Accessories never define species.

---

# 18. Tails

If the species has a tail:

- it should be expressive;
- slightly oversized;
- visible in profile.

The tail contributes to movement and personality.

---

# 19. Hands

Hands are intentionally oversized.

Reasons:

- expressive gestures;
- animation clarity;
- visual friendliness.

Hands should never appear realistic.

---

# 20. Feet

Feet are slightly exaggerated.

Benefits:

- readable running animation;
- stable stance;
- charming proportions.

---

# 21. Clothing Philosophy

Clothing is sporty.

Examples:

- running shirts;
- shorts;
- leggings;
- trainers;
- hoodies;
- tracksuits.

Avoid formal clothing.

---

# 22. Clothing Design

Clothing should use:

- clean shapes;
- bold colour blocks;
- minimal patterns.

Avoid:

- logos;
- text;
- camouflage;
- excessive detail.

---

# 23. Accessories

Accessories personalise avatars.

Examples:

- glasses;
- headbands;
- bows;
- wristbands;
- caps;
- scarves;
- backpacks.

Accessories should remain secondary.

The face is always the focal point.

---

# 24. Facial Expressions

Every avatar should support a consistent expression library.

Minimum expressions:

Happy

Excited

Focused

Surprised

Proud

Thinking

Laughing

Determined

Curious

Sleepy

All expressions remain child-friendly.

---

# 25. Emotion Scale

Expressions should be exaggerated.

Think animated film rather than realistic acting.

Children recognise exaggerated emotions more quickly.

---

# 26. Running Pose

Default running pose:

- torso leaning slightly forward;
- one leg extended;
- opposite arm forward;
- open hands;
- confident smile.

The pose should communicate motion even when static.

---

# 27. Victory Pose

Victory pose should communicate:

- celebration;
- confidence;
- gratitude.

Examples:

- raised hands;
- joyful jump;
- waving.

Never use arrogant body language.

---

# 28. Idle Pose

Idle stance should appear relaxed.

Weight evenly distributed.

Friendly smile.

Subtle breathing motion (future animation).

---

# 29. Defeat Pose

Defeat should communicate:

"I'll do better next time."

Examples:

- hands on knees;
- gentle sigh;
- thoughtful face.

Never depict crying, humiliation or despair.

---

# 30. Character Diversity

Every player should feel represented.

Variation should include:

- skin tone;
- hairstyle;
- eye colour;
- accessories;
- body shape (within style);
- species-inspired features.

Diversity should feel natural rather than emphasised.

---

# 31. Character Age

Characters appear approximately:

8–12 years old.

Even animal-inspired avatars should evoke this age group.

Avoid adult proportions.

---

# 32. Character Personality

Every generated avatar receives a subtle personality.

Examples:

Explorer

Inventor

Athlete

Musician

Scientist

Dreamer

Painter

Gardener

The personality influences biography but not appearance excessively.

---

# 33. Visual Complexity

Characters should remain readable at:

64 px

128 px

256 px

1024 px

Details should scale gracefully.

---

# 34. Animation Readability

Future animations should remain readable using only:

- silhouette;
- body movement;
- timing.

Avoid animations dependent on facial details alone.

---

# 35. Consistency Rules

Every newly generated avatar should appear to have been designed by the same animation studio.

Differences should come from:

- species;
- colours;
- hairstyle;
- accessories;
- personality.

Not from artistic style.

---

# 36. Forbidden Characteristics

Characters must never include:

- realistic violence;
- weapons;
- military equipment;
- horror themes;
- exaggerated muscles;
- visible injuries;
- frightening facial expressions;
- offensive symbols;
- smoking;
- alcohol;
- tattoos with mature themes.

---

# 37. AI Generation Constraints

Every generated character must satisfy:

- exactly one character;
- full body visible;
- facing mostly forward (¾ view preferred);
- transparent background;
- no text;
- no watermark;
- no additional objects unless explicitly requested;
- premium-quality stylised 3D illustration.

---

# 38. Character Evolution

Future cosmetic upgrades may add:

- new outfits;
- seasonal clothing;
- medals;
- backpacks;
- accessories.

Core anatomy must never change.

Players should always recognise their avatar instantly.

---

# 39. Quality Checklist

Before approving any character, verify:

✓ Instantly recognisable silhouette

✓ Friendly facial expression

✓ Large expressive eyes

✓ Child-friendly appearance

✓ Sporty style

✓ Balanced colour palette

✓ Consistent anatomy

✓ No prohibited content

✓ Fits the visual language

---

# 40. Success Criteria

Character design is successful if:

- children immediately form emotional attachment;
- avatars remain recognisable without names;
- different species still feel part of one universe;
- AI-generated characters are visually indistinguishable from manually designed artwork;
- players proudly choose a favourite avatar and continue racing with it over many sessions.

Characters should become companions, not merely game pieces.

---

**End of Part II — Character Design Rules**

# Math Racers — Art Bible

# Part III — UI Style Guide

**Version:** 1.0

---

# 1. Purpose

This document defines the complete user interface language of **Math Racers**.

The UI should feel like a natural extension of the game world.

It should never appear as a traditional "software application."

Instead, every screen should resemble part of an animated movie.

---

# 2. UI Philosophy

The interface follows one principle:

> **"Children should understand what to do before they read anything."**

The UI prioritises:

- recognition over memorisation;
- large touch targets;
- immediate feedback;
- visual clarity;
- positive reinforcement.

---

# 3. Design Principles

Every screen should be:

- simple;
- colourful;
- readable;
- spacious;
- cheerful;
- consistent.

Avoid visual overload.

If something can be removed without reducing usability, remove it.

---

# 4. Layout System

Every page follows the same layout hierarchy.

```
Header

↓

Main Content

↓

Primary Actions

↓

Secondary Actions

↓

Footer (optional)
```

Important actions should always appear in predictable locations.

---

# 5. Grid System

Use an **8 px spacing system**.

Examples:

- 8 px
- 16 px
- 24 px
- 32 px
- 48 px
- 64 px

Avoid arbitrary spacing values.

---

# 6. Corner Radius

Rounded corners are part of the brand identity.

Recommended values:

Small elements: **8 px**

Cards: **16 px**

Dialogs: **24 px**

Large panels: **32 px**

Buttons should never have sharp corners.

---

# 7. Typography

Typography should be:

- rounded;
- friendly;
- highly readable.

Recommended characteristics:

- geometric sans-serif;
- large x-height;
- open letterforms.

Avoid decorative fonts.

---

# 8. Text Hierarchy

Use a clear hierarchy.

```
Page Title

↓

Section Title

↓

Card Title

↓

Body Text

↓

Caption
```

Never rely only on font size.

Weight and spacing also communicate hierarchy.

---

# 9. Buttons

Buttons are among the most important UI elements.

Characteristics:

- rounded;
- colourful;
- slightly elevated;
- soft shadows;
- animated on interaction.

Primary buttons should immediately attract attention.

---

# 10. Button States

Every button supports:

- Default
- Hover
- Pressed
- Focused
- Disabled
- Loading

State transitions should be animated.

---

# 11. Primary Buttons

Primary actions use the brightest accent colour.

Examples:

- Start Race
- Continue
- Create Avatar
- Finish

Only one primary button should dominate each screen.

---

# 12. Secondary Buttons

Secondary buttons are quieter.

Examples:

- Back
- Cancel
- Settings
- Retry

They should never compete visually with the primary action.

---

# 13. Cards

Cards group related information.

Examples:

- Avatar
- Achievement
- Championship
- Statistics

Cards use:

- rounded corners;
- soft shadows;
- generous padding.

---

# 14. Icons

Icons should be:

- simple;
- filled;
- rounded;
- consistent.

Avoid thin outline icon sets.

Children recognise filled icons more easily.

---

# 15. Icon Style

Icons should appear slightly oversized.

They should remain recognisable at:

- 24 px
- 32 px
- 48 px

Avoid intricate details.

---

# 16. Colour Usage

Interface colours communicate meaning.

Examples:

Green

Success

Blue

Primary action

Yellow

Reward

Orange

Warning

Red

Error (used sparingly)

Purple

Special content

Meaning should remain consistent across the application.

---

# 17. Motion

Motion is essential.

Animations should communicate:

- cause;
- effect;
- hierarchy;
- success;
- interaction.

Animation should never exist purely for decoration.

---

# 18. Animation Timing

Recommended durations:

Very Fast

100 ms

Fast

150 ms

Normal

250 ms

Large transitions

350–500 ms

Animations should feel responsive, not sluggish.

---

# 19. Easing

Preferred easing:

Ease Out

Ease In-Out

Spring (for playful interactions)

Avoid linear motion except for progress indicators.

---

# 20. Screen Transitions

Pages should transition smoothly.

Examples:

- fade;
- slide;
- scale.

Avoid abrupt screen changes.

---

# 21. Hover Feedback

Desktop interactions should include:

- slight scale increase;
- brighter shadow;
- subtle colour lift.

Feedback should feel alive without being distracting.

---

# 22. Mathematical Challenges

Math problems are the visual focus during races.

Requirements:

- very large typography;
- strong contrast;
- uncluttered background;
- immediate readability.

Nothing should distract from solving the problem.

---

# 23. Race HUD

The race interface displays only essential information.

Recommended elements:

- current position;
- remaining distance;
- current obstacle;
- timer (if applicable);
- progress indicator.

Avoid unnecessary statistics during gameplay.

---

# 24. Feedback

Correct answers should trigger:

- cheerful animation;
- positive sound;
- brief glow;
- forward movement.

Incorrect answers should trigger:

- gentle shake;
- encouraging message;
- immediate retry or continuation.

Never punish mistakes visually.

---

# 25. Dialogs

Dialogs should appear friendly.

Characteristics:

- rounded;
- centred;
- spacious;
- lightly elevated.

Destructive actions should require confirmation.

---

# 26. Forms

Forms should request only necessary information.

Examples:

Avatar creation:

- species;
- hairstyle;
- colours;
- accessories.

Avoid long forms.

Children should complete most tasks in under one minute.

---

# 27. Navigation

Primary navigation should remain shallow.

Avoid deep menu hierarchies.

The player should reach any major feature within three interactions.

---

# 28. Empty States

Every empty screen should feel inviting.

Example:

"No favourite avatars yet.

Let's create your first racing friend!"

Avoid technical messages such as:

"No records found."

---

# 29. Loading States

Loading should entertain.

Examples:

- running mascot;
- animated maths symbols;
- encouraging tips;
- progress animation.

Never show a blank screen.

---

# 30. Rewards

Rewards should feel celebratory.

Use:

- stars;
- confetti;
- sparkles;
- medals;
- joyful animations.

Celebration should last only a few seconds.

---

# 31. Accessibility

Support:

- keyboard navigation;
- visible focus indicators;
- colour-blind-safe design;
- reduced motion mode;
- scalable text.

Accessibility features should never reduce visual quality.

---

# 32. Responsive Design

Priority order:

Desktop

↓

Laptop

↓

Tablet

↓

Large phone

Layouts should adapt gracefully without redesigning interaction patterns.

---

# 33. Sound & Visual Synchronisation

Visual effects should align with audio.

Example:

Correct answer

↓

Glow

↓

Runner accelerates

↓

Cheer sound

The sequence should feel natural.

---

# 34. Consistency

Every screen should answer the following questions immediately:

- Where am I?
- What can I do?
- What is most important?
- What should I do next?

If the answer is unclear, simplify the design.

---

# 35. Quality Checklist

Every UI screen should satisfy:

✓ Clear hierarchy

✓ Spacious layout

✓ Rounded geometry

✓ Strong readability

✓ Consistent colours

✓ Friendly motion

✓ Accessible controls

✓ Child-friendly interaction

✓ Premium visual quality

---

# 36. Success Criteria

The UI is successful if:

- children understand it without instruction;
- interaction feels joyful;
- gameplay remains the visual focus;
- navigation feels effortless;
- every screen looks like part of the same animated universe.

The interface should disappear behind the experience, allowing players to focus entirely on learning and racing.

---

**End of Part III — UI Style Guide**

# Math Racers — Art Bible

# Part IV — Image Generation Standards

**Version:** 1.0

---

# 1. Purpose

This document defines the production standards for every AI-generated image used in **Math Racers**.

Its objectives are:

- guarantee visual consistency;
- maximise generation quality;
- minimise regeneration rate;
- establish deterministic production workflows;
- ensure all generated assets match the Art Bible.

This document should be considered the official specification for GPT Image prompts.

---

# 2. Design Philosophy

AI is not an artist.

AI is a production tool.

The artistic direction comes from:

- Game Design Document
- Art Bible
- Prompt Bible

The image model is responsible only for rendering.

Creative direction belongs to the project.

---

# 3. Production Pipeline

Every image follows the same pipeline.

```
Structured Metadata

↓

Prompt Builder

↓

GPT Image

↓

Automatic Validation

↓

Human Review (optional)

↓

Asset Library
```

Every generated asset must be reproducible.

---

# 4. Asset Categories

Version 1.0 includes:

### Characters

- avatars
- future NPCs

### UI Assets

- icons
- badges
- medals
- trophies

### Environment

- stadium illustrations
- backgrounds
- loading artwork

### Promotional

- splash screen
- store images
- website artwork

Each category follows different prompt templates.

---

# 5. Image Style

Every generated image should appear as:

> A premium stylised 3D animated illustration from a modern feature-length family animation.

Never imitate a specific studio.

Never reference copyrighted characters.

The artistic style should feel original while evoking the warmth and quality of high-end animated films.

---

# 6. Universal Artistic Requirements

Every image must be:

- premium quality;
- colourful;
- soft;
- optimistic;
- expressive;
- child-friendly;
- timeless;
- highly readable.

The project should never contain assets of mixed artistic styles.

---

# 7. Technical Specifications

Default specifications:

Resolution

1024 × 1024

Aspect Ratio

1:1

Background

Transparent (characters)

Full illustration (environments)

Lighting

Warm daylight

Quality

Highest available

Every production asset should be suitable for future upscaling.

---

# 8. Composition Rules

Images should use:

- clear focal point;
- balanced composition;
- generous negative space;
- readable silhouette.

Avoid crowded scenes.

---

# 9. Character Composition

Character images should satisfy:

- exactly one character;
- full body visible;
- centred composition;
- feet fully visible;
- no cropping;
- facing camera at approximately 30–45°.

This angle provides personality while preserving readability.

---

# 10. Camera

Preferred virtual camera:

- eye level;
- slight perspective;
- medium distance.

Avoid:

- extreme close-ups;
- dramatic low angles;
- exaggerated wide-angle distortion.

---

# 11. Lighting

Lighting should remain consistent.

Requirements:

- warm sunlight;
- soft shadows;
- subtle rim lighting;
- bright atmosphere;
- gentle ambient illumination.

Night scenes are not used in Version 1.0.

---

# 12. Colour Harmony

Colours should follow the palette defined in Part I.

Requirements:

- vibrant;
- harmonious;
- balanced saturation;
- no muddy colours.

Characters should remain readable against any UI background.

---

# 13. Facial Expression

Characters should display positive emotions.

Preferred expressions:

- happy;
- excited;
- curious;
- confident;
- focused;
- proud.

Avoid:

- anger;
- fear;
- sadness;
- disgust;
- aggression.

---

# 14. Anatomy

Characters follow the anatomy rules from Part II.

Requirements:

- oversized head;
- expressive eyes;
- athletic proportions;
- rounded geometry;
- simplified details.

Never generate realistic anatomy.

---

# 15. Clothing

Clothing should be:

- sporty;
- colourful;
- simple;
- readable.

Avoid:

- logos;
- text;
- camouflage;
- military uniforms;
- formal clothing.

---

# 16. Accessories

Accessories should support personality without dominating the design.

Examples:

- bow;
- cap;
- glasses;
- scarf;
- wristband;
- backpack.

Maximum recommended accessories:

Three.

---

# 17. Background Rules

### Character Assets

Transparent background.

No shadows extending beyond the character.

No additional scenery.

---

### Environment Assets

Rich illustrated environments.

Gameplay areas should remain visually calm.

Foreground and background must be clearly separated.

---

# 18. Environment Style

Environment artwork should include:

- rounded trees;
- colourful flowers;
- soft clouds;
- joyful stadiums;
- playful architecture.

Avoid empty or overly realistic landscapes.

---

# 19. Icon Style

Icons should appear:

- colourful;
- rounded;
- simplified;
- slightly three-dimensional.

Avoid:

- thin outlines;
- monochrome glyphs;
- complex symbolism.

---

# 20. Badge Style

Achievements should resemble collectible enamel pins.

Characteristics:

- gold trim;
- colourful centre;
- glossy finish;
- embossed appearance.

Badges should feel rewarding.

---

# 21. Trophy Style

Trophies should appear:

- playful;
- prestigious;
- oversized;
- polished.

No sharp edges.

No realistic metal scratches.

---

Every production prompt follows the same logical structure.

```
Subject

↓

↓

Personality

↓

↓

Lighting

↓

Composition

Technical Constraints

# 23. Prompt Determinism

Prompt generation should be deterministic.

Identical metadata should always produce identical prompts.

Creative variation comes from the image model—not from prompt randomness.

---

# 24. Negative Constraints

Every generation should explicitly avoid:

- text;
- logos;
- watermarks;
- signatures;
- extra characters;
- cropped body parts;
- horror;
- weapons;
- blood;
- violence;
- mature themes;
- photorealism;
- anime;
- comic-book style;
- low-detail rendering.

Every generated image should pass the following checks.

### Technical

✓ correct size

✓ transparency (when required)

✓ readable format

✓ no corruption

---

### Artistic

✓ consistent style

✓ correct proportions

✓ attractive composition

✓ balanced colours

✓ expressive face

✓ premium quality

---

### Gameplay

✓ recognisable at small sizes

✓ readable silhouette

✓ no distracting details

# 26. Regeneration Policy

Regenerate if:

- body is cropped;
- multiple characters appear;
- expression is inappropriate;
- anatomy is broken;
- colours clash;
- composition is poor;
- style differs from the Art Bible.

Never manually edit inconsistent assets.

Always regenerate.

---

Every generated asset should record:

- asset ID;
- asset type;
- creation date;
- prompt version;
- model;
- generation pipeline version;
- metadata hash.

Assets should always be traceable.

Assets are immutable.

Version 3
```

Older versions remain reproducible.

The same production pipeline should support:

Human review is optional.

Generation should prioritise quality over speed.

Image generation requests must never include:

- database identifiers;
- internal system prompts;
- infrastructure details;
- user analytics.

Only creative metadata is sent to the image provider.

Before accepting any asset, verify:

✓ Premium stylised 3D illustration

✓ Rounded design language

✓ Warm lighting

✓ Child-friendly

✓ Positive emotion

✓ Consistent palette

✓ Clean silhouette

✓ No prohibited content

✓ Matches existing assets

If any item fails, regenerate.

---

# 35. Success Criteria

The image generation system is considered successful if:

- AI-generated assets are visually indistinguishable from hand-crafted illustrations;
- different asset categories appear to belong to the same universe;
- regeneration rates remain low;
- players consistently recognise the game's visual identity;
- future assets can be added without revising the artistic direction.

The quality bar should remain high enough that players perceive the artwork as the product of a professional animation studio rather than an automated image generation system.
